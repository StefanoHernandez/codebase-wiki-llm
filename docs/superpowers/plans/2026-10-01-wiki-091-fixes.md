# Codebase Wiki LLM 0.9.1 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development.

**Goal:** Ship the four reviewed reliability fixes as 0.9.1 on main.
**Architecture:** Canonical prompts and scripts remain the single source;
generated host packages distribute identical behavior. A stdlib Python
validator complements the agent's semantic lint; hooks stay POSIX shell.
**Tech Stack:** Markdown, POSIX sh, Git, Python 3.10+ standard library.
**Spec:** `docs/superpowers/specs/2026-10-01-wiki-091-fixes-design.md`.

## Global Constraints

- Edit `canonical/`, never generated `plugins/` or `skills/` directly.
- Hooks remain POSIX shell plus Git and never block the agent.
- Validator is read-only, stdlib-only, shipped inside maintainer skills.
- Validator needs Python 3.10+ only for deterministic lint; no implicit install.
- `🟢` means proven completion; `⚫` means explicit human closure without proof.
- Existing Core map paths, translated markers and v1 fallback stay usable.
- Codebase version becomes `0.9.1`; SecondBrain stays unchanged.
- User authorized main push and `v0.9.1`; real-host checks stay pending.

## Review Focus

- Repeated content changes at the same path, including initially dirty paths.
- Installed validator independent of repository development scripts.
- Adopted/localized paths and valid sources with line/symbol suffixes.
- Distinct proven completion and human-authorized unproven closure.
- Already accepted decisions and removal of duplicated handoff task status.

### Task 1: Fingerprint reminder coverage

**Files:** `canonical/codebase/scripts/remind-wiki-sync.sh`,
`scripts/test-remind-wiki-sync.sh`.

**Interface:** Existing hook CLI and output format stay unchanged. State
records path plus content fingerprint, including deletion state; older state
files must fail safely rather than hide a new change.

- [ ] Add failing regressions for a second edit after coverage, a second edit
  to an initially dirty file, and changed content at an already-notified path.
- [ ] Run the reminder tests and record the observed failures.
- [ ] Implement current-state fingerprints with correct quoting for spaces;
  preserve quiet unchanged states and committed-change detection.
- [ ] Run reminder tests and shell syntax checks; self-review; commit only
  canonical script and its tests. Report commands and results in the task report.

### Task 2: Align task status, handoff and decisions

**Files:** `canonical/codebase/default-schema.md`, `maintainer.md`,
`references/{agent-context,agent-handoff,work-tracker,decision}-template.md`,
`workflows/{wiki-init,wiki-ingest,wiki-sync,wiki-lint}.md`.

**Interface:** Tracker Done rows have `ID | Status | Goal | Closed | Criteria
met | Evidence`; `⚫` has a recorded human closure, `🟢` proven criteria.
Handoff says `Tracker IDs` and uses `<wiki-root>/<Core map log path>` and
`<wiki-root>/<Core map tracker path>` in sources. Accepted decisions carry
explicit recorded authority and may be written by sync without a new
permission to document them; unresolved agent ideas remain proposed.

- [ ] Update the reference format and rules without broad unrelated changes.
- [ ] Check the four concrete scenarios: proven green closure, unproven human
  black closure, already accepted choice and unresolved agent proposal.
- [ ] Ensure decisions and other content templates use real source-path
  placeholders, not descriptive phrases; init resolves them.
- [ ] Inspect every affected instruction for contradiction; self-review and
  commit canonical files. Semantic behavior is verified by review, not
  falsely reported as a live host test.

### Task 3: Package deterministic wiki validation and release artifacts

**Files:** new `canonical/codebase/scripts/validate-wiki.py`,
`scripts/test-wiki-validator.py`, `scripts/test-wiki-validator.sh` as needed;
`scripts/generate-codebase-packages.py`, `scripts/test-generators.sh`,
`scripts/run-tests.sh`, `scripts/check-generated.sh`,
`canonical/codebase/workflows/wiki-lint.md`, `canonical/codebase/maintainer.md`,
`canonical/codebase/VERSION`, `README.md`, `docs/release-checklist.md`,
and regenerated `plugins/`, `skills/`, `.claude-plugin/marketplace.json`.

**Interface:** `python3 <maintainer>/scripts/validate-wiki.py <wiki-root>`;
exit 0 valid, 1 findings, 2 invocation/config errors. Detect repo-relative
sources from the target root, not the installed script location. Do not
depend on this repo's `scripts/` or third-party packages. Existing
`scripts/validate-agent-handoff.py` remains a continuity compatibility CLI.

- [ ] Implement only the documented structural format using standard library

- [ ] Ship the canonical script in all four maintainer distributions, test

- [ ] Run deterministic validation first in lint, with explicit unavailable

- [ ] Bump to `0.9.1`; update release notes and dependency/validation docs.
