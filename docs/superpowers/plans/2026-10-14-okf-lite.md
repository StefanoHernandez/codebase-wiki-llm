# OKF-lite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `type`, `description`, `status`, `generated`, optional `verified` to the codebase-wiki frontmatter, additively, with lint reporting trust tiers.

**Architecture:** Edit only `canonical/codebase/*` and two scripts, bump the version, regenerate host packages. The handoff validator is the only executable code; everything else is prompt text pinned by grep checks.

**Tech Stack:** Markdown prompts, Python 3 (stdlib), bash, `scripts/generate-codebase-packages.py`.

**Spec:** `docs/superpowers/specs/2026-10-14-okf-lite-design.md` (read it; "Regole 1–5" are copied verbatim into the canonical files, not paraphrased).

## Global Constraints

- Additive only: a page with `updated` and none of the new fields stays valid everywhere.
- `status` ∈ `draft | stable | deprecated`, default `stable`.
- Actor: `human:<id>` or `<host>/<model>`, host ∈ `claude-code`, `codex`, `antigravity`; unknown model → `<host>/unknown`.
- Agents never write `verified`; `index.md` and `log.md` get no `type`.
- Version `0.9.0` in all four places (3 in the generator, 1 in `.claude-plugin/marketplace.json`).
- Never edit generated files under `plugins/` or `skills/`; edit `canonical/` and regenerate.
- Paths in canonical text use `<wiki-root>/`, never a literal `wiki/`.

## Review Focus

1. Legacy page (only `updated`) passes the validator and is `info` in lint, never an error. Pinned in Task 1 and Task 3.
2. `generated` as an inline map `{ by, at }` is accepted by the hand-rolled frontmatter parser. Pinned in Task 1.
3. `wiki-sync` must not write `verified`. Pinned by grep in Task 3.
4. `overview-<project-slug>.md` maps to `type: Overview`. Pinned by grep in Task 2.
5. Configurable wiki root: no literal `wiki/` added by this change. Pinned by grep in Task 4.
