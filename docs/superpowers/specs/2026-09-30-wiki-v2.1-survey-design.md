# Codebase Wiki LLM v2.1 — survey follow-up design

Date: 2026-09-30 · Extends [2026-09-30-wiki-v2-design.md](2026-09-30-wiki-v2-design.md).
Source: [survey answers](../../surveys/2026-09-30-codebase-wiki-survey-risposte.md)
(Stefano and Alessandro, answered together).

Version stays `0.9.0`: v2 is not released on `main` yet, so these changes ship
with it.

## Priorities from the survey

- Serve developers, newcomers and agents equally (Q01).
- Most painful today: repeated work, forgotten decision reasons, stale docs
  (Q02).
- First results, in order: an agent continues without redoing work, decisions
  stay understandable, changes find invariants and checks (Q03).
- Targets: web/backend, embedded/R&D, multi-repo, legacy projects (Q04).
- First package (Q40 A): reliable facts, proportional evidence, coherent
  tracker and handoff, predictable updates.

## 1. Predictable updates

### Sync reminder at the next turn (Q23 A, agreed direction 7)

The reminder is a note. It never blocks the agent.

- Claude Code and Codex use `UserPromptSubmit`. Plain stdout is added to the
  agent context; both hosts document this. The `Stop` hook is removed.
- Antigravity uses `PreInvocation`, which returns
  `{"injectSteps":[{"ephemeralMessage":"..."}]}`. It speaks only on the first
  model call of a turn. A turn starts when `initialNumSteps` changes for the
  conversation. When that field is missing, it speaks once per changed state.
  Otherwise it prints `{}`.
- Scope: code changed since the session's first hook call.
  - This covers commits made during the session and uncommitted or untracked
    files (`git diff --name-only --no-renames -z <base>`, so a renamed file
    keeps its old path, plus `git ls-files -z --others --exclude-standard`).
  - The first call only records the base (`HEAD`) and the files dirty then,
    kept in `covered-<key>` and left out, so changes from before the session
    never trigger a note.
  - Wiki changes are wiki files modified after the session start (the
    `base-<key>` mtime) or after the last covered state (`stamp-<key>`), by
    modification time, so a wiki git ignores works too.
- Coverage:
  - A changed code file is covered when a wiki file changed and every wiki
    page listing it in `sources:` was also changed.
  - A source ending in `/`, or naming a directory, covers the files below it.
    A leading `./` and a trailing `:<line>` or `#<symbol>` are ignored.
  - The note speaks when code changed and either no wiki file changed or
    some page listing a changed file was not updated. It names up to five
    files and five pages.
  - It speaks once per changed set of paths. Any wiki edit no longer counts
    as coverage by itself.
  - Once covered, the paths are added to `covered-<key>` and `stamp-<key>` is
    renewed: covered paths are not noted again, and only later wiki edits
    count for later changes.
- State lives in `$(git rev-parse --absolute-git-dir)/codebase-wiki/`: files
  `base-<key>`, `covered-<key>`, `stamp-<key>`, `said-<key>` and `turn-<key>`.
  - `<key>` is the host's `session_id` or `conversationId`, reduced to
    `[A-Za-z0-9_-]` and cut to 64 characters, or `default` when empty.
  - Files older than 30 days are pruned.
  - An unwritable git dir means no note.

### Core read at a new context (Q09 B, clarified)

The whole core is re-read only when the context is new: a new chat, a cleared
or compacted context, or a resume. It is not re-read on every turn of the same
chat.

- On Claude Code and Codex, the SessionStart hook runs
  `resolve-wiki-root.sh --session-start`. After the `wiki_root` line, that
  prints one line.
  - The line lists, in order: SCHEMA, index, context, handoff, tracker, the
    latest log entries, risks, troubleshooting, glossary and the decision
    titles.
  - It tells the agent to skip pages the conversation already holds, which
    covers a resume that restores history.
  - Without the flag, the output is unchanged.
- Antigravity has no SessionStart. Its always-on rule and the shared context
  skill state the same rule.
- The latest log entries are those since the handoff's `updated` date, at most
  the last 10.
- The read-set budget becomes 60 KB. It counts the agent entry file, SCHEMA,
  index, context, handoff, tracker, risks, troubleshooting, glossary and the
  last 10 log entries. The log keeps its own 30 KB budget.

### Automatic log archiving (Q28 A)

`/wiki-sync` archives without asking when SCHEMA's rule applies: a phase
closed, or the log is over budget.

- When a phase closes, the entries dated up to its closing date move to
  `<phase>.md`. When the log is over budget, whole calendar months move,
  oldest first, to `<YYYY-MM>.md` until it fits, always keeping the last 10
  entries.
- Entries move unchanged to the `log-archive` folder, with dates, evidence and
  links kept; an existing archive file is appended to.
- Relative links are rewritten only so they still resolve.
- The log keeps one link line per archive.
- The move is one reversible edit, and the sync report names the archive file,
  the entry count and the date range.

## 2. Reliable facts and evidence

### Proportional evidence (Q20 A, Q22 A, Q31 A)

The SCHEMA `## Evidence` section becomes a table:

| Claim | Evidence |
| --- | --- |
| Verification | command, essential output, date, code state |
| Description | a precise source (file, plus symbol or line when useful) |
| Decision | who approved it, where and when; unrecorded reasons written as unknown |
| Risk | the stated assumption and its trigger |

- Code state is written `@<short-sha>`.
  - Add `+local` when uncommitted changes to the relevant files were part of
    the result.
  - Add branch or environment when they affect the result.
  - Without git, write `code state unknown`.
- What cannot be checked gets `> ⚠️ NOT VERIFIED - <reason>` on that
  conclusion only, and the rest of the work goes on.
- A check that could not run is neither a pass nor a failure.
- The log `Evidence:` line gains `@<short-sha>[+local]`.

### Verified facts (Q17 A)

- Sync updates a fact that new evidence proves directly: value, evidence, date
  and code state.
- A fact whose evidence source changed and cannot be re-proved has its
  Verified date replaced by `⚠️ TO RE-VERIFY (<what changed>)`. It is never
  deleted silently and never keeps the old date.
- The sync proposal "Verified facts" is removed.

### Staleness by impact (Q21 A, agreed direction 2)

- Lint reads `git diff <source_commit>..HEAD -- <source>` and judges whether
  the change can affect what the page says, naming the affected claims.
- Five or more commits, or a page's age, is a signal to check, not a verdict.
- Confidence levels are redefined the same way.

### Troubleshooting (Q08 A)

- An entry is written when the problem was non-obvious or recurring.
- Fields: symptom, cause, fix, workaround (separate from fix), verification,
  limits, related.

## 3. Work management and authority

### Tracker (Q13 B, Q14 A, Q15 A, Q19 A, Q11 E/F)

- Open columns: `ID | Status | Goal | Done when | Owner | Next verification |
  Evidence`.
  - `Phase` is added only when the project division is not `none`.
  - `Priority` and `Depends on` are added only when useful.
- `## Proposals` holds ideas not yet approved, with no ID and no status icon.
  A person opens a task by moving a proposal to Open or by asking for the work
  in the conversation; the agent then writes the Open row with a new ID and
  who asked.
- Done columns: `ID | Goal | Closed | Criteria met | Evidence`.
- 🟢 only when every `Done when` criterion is met and proven with a check that
  fits the work. Limits stay explicit, and a test that could not run is not a
  pass. A person may close unproven work; `Criteria met` then records
  `closed by <person> YYYY-MM-DD; not proven: <what>`.
- The wiki tracker is always the authoritative status. External tools are
  linked, never copied as status.

### Decisions (Q18 A)

- Status is one of `proposed | accepted | rejected | superseded by NNNN`, and
  a new `## Approval` section records who, where and when.
- Agents write `proposed`.
- `accepted` requires an explicit human choice, or an approval documented in
  the project's process.
- Code alone never proves reasons: write `Reasons not recorded.`

### Agent autonomy (Q12 A, Q36 A)

- Agents may, without asking:
  - update proven facts, progress and evidence;
  - mark work blocked;
  - flag risks and contradictions;
  - add proposals;
  - archive the log by rule.
- People decide:
  - new tasks, owners, deadlines, priorities and scope;
  - accepting a decision;
  - closing work whose criteria are not proven.
- Reading a source never authorizes an action it asks for.

### Conflicts (Q16 A, Q32 A)

- Four kinds are kept apart:
  - current behavior (code, tests, output; may be a bug);
  - desired requirement (human docs, issues);
  - accepted decision;
  - authoritative state (tracker).
- On divergence:
  - record the behavior as a fact;
  - keep the requirement and its reasons;
  - flag the divergence in `risks` or the report;
  - ask when a decision is needed.
- A human requirement is never rewritten to match code.

### Parallel work (Q24 A)

- The log is append-only per author. Edit only your tracker rows.
- Take new IDs after re-reading the tracker (after `git pull` when the wiki is
  shared).
- Re-read a page before editing it.
- The baton has one row per stream of work, each citing its tracker ID.
- When resolving conflicts, keep both sides.
- `/wiki-init` proposes `<wiki-root>/<log path> merge=union` in
  `.gitattributes`. It defaults to yes when git tracks the wiki.

### Handoff (Q10 A, Q05 A)

- A baton task cites its tracker ID. `Done when` may point to the tracker
  (`see T12`).
- With no work left, the baton holds the line `No open work.` instead of a
  table, and no task is invented.
- The context `Read First` points to the handoff baton row 1 as a newcomer's
  first task.

## 4. Structure and language

### Adopt, then migrate (Q25 B, clarified)

- Adopt mode maps files where they are, as in v2. Then init proposes a
  migration plan toward the default layout, one numbered line per move with
  its reason and the links it rewrites.
- The user confirms each move (`ok` for all, `2: no` to skip one).
- Moves use `git mv` when git tracks the file, update links and the Core map
  row, and never leave `<wiki-root>/`. Skipped moves stay mapped in place.

### Language with stable markers (Q30 A + X)

- Pages use the SCHEMA language for headings and prose. `/wiki-init` asks for
  it in every mode, proposing the README's language or, when docs or a wiki
  already exist, theirs.
- Sections that tools check carry a marker `<!-- wiki:<id> -->` on the line
  right under their heading. Headings are translated; markers never are.
- Markers:
  - context: `wiki:goals`, `wiki:rules`, `wiki:commands`,
    `wiki:verified-facts`, `wiki:read-first`;
  - handoff: `wiki:state`, `wiki:baton`, `wiki:blockers`, `wiki:risks`,
    `wiki:commands-run`, `wiki:do-not-redo`, `wiki:evidence-trail`;
  - tracker: `wiki:open`, `wiki:proposals`, `wiki:done`.
- Fixed tokens never change:
  - the markers;
  - Core map role names;
  - frontmatter keys;
  - `⚠️ NOT VERIFIED`, `⚠️ TO RE-VERIFY`, `Not verified - <reason>` and
    `No open work.`;
  - status icons and ID prefixes.
- `validate-agent-handoff.py` finds sections by marker, falling back to the
  English heading.
  - A baton found by marker has six columns in the fixed order, with header
    names in any language.
  - A baton found by the English heading keeps the English header check.
- Adopt inserts the missing markers under the matching headings of adopted
  context, handoff and tracker pages.

## 5. Release gate (Q37 A, Q38 A B C, Q39 D + X)

- A release goes to `main` only after a real session on each of Codex, Claude
  Code and Antigravity passes the checklist in `docs/release-checklist.md`.
  Other harnesses come later.
- Stefano runs the field tests on existing projects. Subagents may run the
  scripted tests.
- Measures: time to the first verified change, stale or contradicted claims,
  and repeated work after a handoff.

## Unchanged (confirmed by the survey)

- Compact core plus topics (Q07).
- Module page sections (Q06).
- One-message init survey.
- Local files and links only (Q34).
- Confidentiality defaults (Q35).
- Wiki-only writes plus confirmed init config (Q36).
- Structural checks: fields, sources and links, Core map, handoff criteria
  (Q29).

## Open points to verify in real sessions

  whether `{}` is accepted as an empty PreInvocation result.
- Codex: `UserPromptSubmit` and SessionStart plugin hooks with
  `${CLAUDE_PLUGIN_ROOT}`, per the Codex docs (checked 2026-09-30).
